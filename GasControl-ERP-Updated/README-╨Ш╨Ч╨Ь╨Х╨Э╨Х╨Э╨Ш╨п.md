# GasControl ERP — изменения авторизации и реестров

Сохранена исходная структура и существующие разделы проекта. Добавлено:

- Вход через Google OAuth.
- При первом входе автоматически создаётся профиль с ролью `client`; пользователь заполняет ФИО и ИИН.
- Клиент не получает доступ к рабочим разделам, пока администратор не назначит роль `dealer` или `operator`.
- Администратор видит новые профили в разделе «Пользователи и роли», может нажать «Назначить», выбрать роль и активность.
- В таблице пользователей показывается число записанных показаний по каждому пользователю.
- Дилер может записывать показания абонентов; каждая операция хранит UID, имя и email автора.
- Поиск абонентов и операций включает ИИН, номер счёта-фактуры, ФИО, лицевой счёт и пользователя.
- Пагинация реестра абонентов и истории операций — по 25 строк.
- Добавлены поля ИИН и номер счёта-фактуры в карточку абонента и Excel-импорт/экспорт.
- Обновлены стили входа и элементов управления без эмодзи.

## Обязательная настройка Firebase

1. В `firebase-config.js` укажите конфигурацию своего Firebase Web App.
2. Firebase Console → Authentication → Sign-in method → включите **Google**.
3. В Authentication → Settings → Authorized domains добавьте домен сайта (например, домен GitHub Pages).
4. Firebase Console → Firestore Database → Rules: опубликуйте содержимое `firestore.rules` из этого архива.
5. Первого администратора нужно назначить вручную: выполните Google-вход под нужным аккаунтом, затем в Firestore в документе `users/{UID}` измените `role` на `admin` и оставьте `active: true`. UID доступен в Firebase Authentication → Users. После этого администратор сможет назначать остальные роли из интерфейса.
6. Если в проекте уже есть пользователи, у которых в `users/{UID}` нет `active: true`, установите это поле в `true`; правила намеренно блокируют неактивные профили.

## Роли

- `client` — профиль заполнен, ожидает назначения роли.
- `dealer` — ввод показаний абонентов и просмотр истории операций.
- `operator` — рабочие разделы оператора.
- `admin` — управление ролями и настройками.
- `accountant`, `viewer` — прежние роли сохранены.

Перед использованием на реальных данных проверьте правила Firebase на тестовом проекте и сделайте резервную копию Firestore. Firebase Rules нужно публиковать отдельно — изменения локальных файлов сами по себе не меняют правила в облаке.
