# GasControl ERP — Firebase version

Современная веб-система учёта дилеров, ШРП, абонентов, показаний и начислений. Проект подготовлен для GitHub и Firebase Hosting.

## Возможности
- Вход через Firebase Authentication (email/password).
- Роли: `admin`, `operator`, `accountant`, `viewer`.
- Серверные правила доступа Firestore в `firestore.rules`.
- Реестр дилеров и ШРП.
- Реестр абонентов: ручное добавление, поиск, экспорт Excel.
- Импорт абонентов из `.xlsx`, `.xls`, `.csv` с предварительной проверкой строк и дубликатов.
- Шаблон Excel `Шаблон_импорта_абонентов.xlsx`.
- Ввод показаний и расчёт начислений с сохранением применённого тарифа.
- История операций и журнал аудита.
- Настройка тарифа администратором.
- Экспорт реестров в Excel.

## Важно перед запуском
Это полноценная клиентская интеграция с Firebase, но **реальное развёртывание требует настройки вашего Firebase-проекта**. В архиве не может быть ваших учётных данных или созданного в вашей консоли проекта. Не публикуйте сервисные аккаунты и приватные ключи.

## 1. Создайте Firebase-проект
1. Откройте https://console.firebase.google.com/ и создайте/выберите проект.
2. В Authentication → Sign-in method включите Email/Password.
3. В Authentication → Settings → Authorized domains добавьте домен сайта (например, домен GitHub Pages, если используете его).
4. В Project settings → General → Your apps создайте Web app и скопируйте конфигурацию.
5. В Firestore Database создайте базу в подходящем регионе.

## 2. Укажите Firebase config
Откройте `firebase-config.js` и замените все `YOUR_...` / `PASTE_...` на значения Web app из Firebase Console. Конфигурация web app сама по себе не является серверным секретом; безопасность обеспечивают Authentication и Firestore Security Rules.

## 3. Установите правила
В Firebase Console → Firestore Database → Rules вставьте содержимое `firestore.rules` и нажмите Publish. Либо установите Firebase CLI и выполните `firebase deploy --only firestore:rules`.

**Не запускайте систему с открытыми правилами `allow read, write: if true`.**

## 4. Создайте первого администратора
1. В Firebase Console → Authentication → Users → Add user создайте пользователя с email и паролем.
2. Скопируйте его UID.
3. В Firestore создайте коллекцию `users`, документ с ID, равным UID пользователя.
4. Добавьте поля:
   - `displayName` (string), например `Главный администратор`
   - `email` (string), email пользователя
   - `role` (string) = `admin`
   - `active` (boolean) = `true`
5. Выйдите и войдите в приложение заново.

Профиль пользователя не создаётся автоматически при регистрации: это сделано намеренно, чтобы пользователь не мог назначить себе роль. Администратор может создавать профили следующих пользователей в разделе «Пользователи и роли», предварительно создав их в Authentication.

## 5. Роли
- `admin` — все разделы, назначение ролей, настройки.
- `operator` — дилеры/ШРП, абоненты, показания и операции.
- `accountant` — просмотр финансовых операций и обзор.
- `viewer` — только обзор.

Правила Firestore — основной барьер доступа. Скрытие вкладок — только удобство интерфейса.

## 6. Импорт Excel абонентов
1. Откройте раздел «Абоненты».
2. Скачайте `Шаблон_импорта_абонентов.xlsx`.
3. Заполните строки, не меняя названия колонок.
4. ШРП можно указать в колонке `srpName` (должно совпадать с названием в реестре) либо выбрать ШРП по умолчанию в интерфейсе.
5. Выберите файл → «Проверить файл» → проверьте ошибки → «Импортировать проверенные строки».
6. При импорте доступна политика дубликатов: пропустить или обновить по `accountNumber`.

Обязательные колонки:
- `accountNumber` — уникальный лицевой счёт
- `name` — ФИО / название абонента
- `address` — адрес
- `meterNumber` — номер счётчика
- `currentReading` — начальное показание (число не меньше 0)

Необязательные колонки:
- `phone`
- `srpName`

Импорт использует пакетную запись Firestore и ограничен 450 строками за один запуск, чтобы оставить место для записи журнала аудита.

## 7. Локальный запуск и публикация
Для локального запуска можно использовать любой статический сервер, например VS Code Live Server. Для Firebase Hosting:
```bash
npm install
npx firebase login
npx firebase use --add
npx firebase deploy
```
При `firebase use --add` выберите свой проект. Создайте `.firebaserc` с вашим Project ID или используйте интерактивную настройку CLI.

## 8. Ограничения и обязательная проверка перед промышленной эксплуатацией
- Это клиентское приложение; все операции должны проверяться Security Rules. Для строгой финансовой модели рекомендовано перенести критические расчёты и проводки в Cloud Functions / серверную транзакционную логику.
- Веб-конфигурация Firebase должна быть заполнена владельцем проекта.
- Прямое подключение к физическим газовым счётчикам не реализовано.
- Платёжный шлюз и подтверждение фактической оплаты не реализованы.
- Для большого реестра лучше использовать пагинацию, а не загружать до 1000 документов за запрос.
- Перед производственным использованием протестируйте правила, импорт и сценарии расчёта на тестовом проекте.
